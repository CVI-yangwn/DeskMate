# 意图层：把“看屏幕”升级成“看懂在做什么”

> 来源：*Act2Intention: A Benchmark For Developing Active Mobile Agents Through Inferring User Intention from GUI Actions*（arXiv:2608.14132，IMWUT 2026）。
> 这里记录我们借鉴了什么、故意没照搬什么，以及对应的代码位置。

## 1. 论文里真正可迁移的三件事

1. **中间表示**：不把原始 GUI 像素直接喂给意图模型，而是先把每个原子动作压成一句话
   `[On/In] [App], [Action], to [Purpose]`，再在这串描述上做意图归纳。
2. **意图是“段”，不是“标签”**：一段连续动作对应一个自包含目标，边界出现在换应用、
   目的变化、交互断点上；一段里可以有多个动作。
3. **主动服务要有闸门**：预测 → 置信度自评（θ=0.60）→ 用户确认 → 才执行。

## 2. 映射到 DeskMate

| 论文 | DeskMate | 说明 |
|---|---|---|
| 原子动作 `a_t` + 观测 `o_t` | 一次扫描的 `activity`（含 app / title / OCR 证据） | 粒度是 12–60 秒，不是秒级点击 |
| 动作描述 `d_t` | 视觉模型已经产出的那句 `activity` | 不再多调一次 VLM，省钱也少一层误差 |
| 会话切分 | `advanceSegment()` 本地规则 | 换应用 / 断档 8 分钟 / 同应用超 45 分钟且语义漂移 |
| 意图 `I_i` | `intentions` 表 + 面板“此刻”里的意图行 | 一句 ≤40 字、带起止时间与步数 |
| 用户画像 `P` | 用户自写 persona + `buildBehaviorProfile()` 的 7 天统计 | 统计是确定性的，不编造 |
| 预测 `Î_{t+1}` | `predictNextIntention()`：最近 6 条意图 + 时段 + 画像 | 只猜“下一步”，要求具体到对象 |
| 置信度回退 | `gatePrediction()`，θ=0.60，discard 只记录不打扰 | 空话/低分/刚被否过都拦掉 |
| 用户确认 | 面板“对 / 不是”，写入 `outcome` | “不是”会在 2 小时内抑制相似猜测 |
| 经验引导执行 | **没有对应实现** | DeskMate 没有 GUI 执行能力，不假装能代操作 |

## 3. 故意没照搬的地方

- **不做逐动作 VLM 描述**：扫描间隔 60 秒，一个“动作”本来就是一屏状态；再拆细只会更贵更吵。
- **不让模型切段**：切段错了会连带标签错，规则可解释、零成本、可单测。模型只负责命名。
- **不追求“事件级”预测**：论文是移动端 App 内任务；桌面上“下一件事”常常跨应用，
  所以只在有 3 条以上历史意图、且置信度过线时才开口。
- **不实现自动执行**：没有辅助功能级 GUI 控制，任何“帮你点了”都是假的。

## 4. 运行链路

```text
扫描 (60s / 窗口变化 12s)
  └─ 视觉分析 → activity
       ├─ memory.appendObservation()      # 原有：活动时间线
       └─ trackIntention(step)            # 新增：意图累积
            ├─ 同一段 → 继续攒
            └─ 该切了 → labelIntentionSegment()
                 ├─ DeepSeek 命名（失败回退本地 localIntentionText）
                 └─ memory.addIntention() → 面板可见

主动判断（未静音 / 未勿扰 / 未冷却）
  ├─ 陪伴时刻优先（一天一次）
  ├─ maybeIntentionSuggestion()
  │    ├─ 25 分钟内不重复猜
  │    ├─ 上一条还没回应就先不叠新的
  │    ├─ gatePrediction(θ=0.60) → discard 只入库
  │    └─ push → 气泡/语音「我猜你接下来要……」
  └─ 否则走原来的通用观察
```

## 5. 数据与开关

```sql
intentions(id, app, title, text, start_at, end_at, step_count, confidence, source, created_at)
intention_predictions(id, text, app, confidence, decision, reason, created_at, outcome, outcome_at)
```

- `source = deepseek | local`：`local` 表示这句是模板兜底，不是模型归纳的。
- 环境变量 `DESKMATE_INTENT_PREDICT=0` 关闭主动预测（仍会记录意图）。
- 预测同样受 `dnd`、安静时段、`intent-predict` 的“连续被关 2 次静默 7 天”约束。

## 6. 已知不足

- 分段只看应用与时间，**跨应用的一件事**（查文档 → 改代码）会被切成两段。
- 意图文本上限 40 字，复杂任务会被压扁；这是刻意的取舍，避免面板变成日志。
- 预测没有长期记忆（上周同时间在做什么），论文也把这条列为 future work。
- `getCurrentIntention()` 用“结束在 30 分钟内”近似“正在进行”，长时间不扫描会偏保守。


## 7. 注意力归属：屏幕上有 B ≠ 你在做 B

早期版本把两屏内容「综合成一句话」，于是很容易出现「一边看 A 一边聊 B」——
意图层拿到的是混合物。现在分三层处理：

1. **取景分主次**：第 1 张截图是前台屏，`activity` 只允许描述它；
   其余屏标成「副屏，仅环境」，只有直接支撑前台任务时才进 `evidence`，
   无关内容进 `ambient` 数组（单独一条线索，不参与意图）。
2. **提示词禁止合并**：明确写「禁止一边……一边……式的合并；副屏在跑别的任务、聊天、通知都不算」。
3. **时间平滑**（`src/main/salience.ts`）：
   - 换应用 → 立刻接受（真实切换）；
   - 同一应用里的新说法 → 要连续两帧才算数；
   - 连续三帧都在变 → 接受（说明画面真的变了，不是噪声）；
   - 和上一句相似（≥0.55）→ 直接接受，避免「换个说法」被当成打断。

被拒绝的那一帧只维持旧状态，不会写进意图段，所以通知、弹窗、「看一眼副屏」都不会污染主线。


## 8. 别把「看过的东西」拼成一件

原来切段只看「换 App + 时间」，于是在同一个浏览器里看了十个文档，也只会被写成一条意图。
现在多了一层**实体**：

- `extractEntity()` 从窗口标题里剥出「正在处理的东西」（文件名 / 页面标题），
  标题为空或太泛（未命名、新标签页）时才退回 URL；
- 同一 App 内实体变了，就切段；只有跨一次扫描（≥20s）才算，避免标题抖动把段落切碎；
- 实体写进 `intentions.entity` 和 `activity_log.entity`，可以直接查「今天看了哪些文件」。

标题优先于 URL 是踩过坑的：AXDocument 时有时无，一会儿 URL、一会儿标题，
同一页会被判成两件事。现在标题一直有、同一页稳定。

已知局限：实体是**页面级**的，不是话题级。同一页里从「API 鉴权」读到「限流策略」，
仍然算同一件事——再细就要做话题切分（例如用 OCR 标题层级或光标段落变化），成本高得多。
