# 陪伴与长期记忆：别人做了什么，DeskMate 可以借什么

> 个人自用视角，不讨论商业竞争。  
> 目标：让 agent 知道“我今天干了什么”，长期下来知道“我是什么样的人、有什么习惯”。  
> 检索时间：2026-11-12。  
> 更新：DeskMate 已落地最小版本——今天锚点、承诺清单、次日 callback、晚间一句；见 README「今天 / 陪伴记忆」。

---

## 0. 先说结论

“知道一天干了什么”和“知道我的习惯”是两件事，需要三套东西：

1. **一天的时间线**：自动记录 + 切成“活动卡片”，不是 raw 截图，也不是手动计时。
2. **长期记忆**：事实、人物、项目、承诺、偏好，分层保存，可检索、可修正、可遗忘。
3. **习惯模型**：从多天的时间线里挖模式，先作为“候选”，被用户确认后才算“事实”。

大多数产品只做好了其中一层：

- **Dayflow** 把“一天的时间线”做得最好：自动 timeline、daily standup、weekly review、和日记对话、Markdown 导出。
- **Miru** 把“陪伴型长期记忆”做得最好：午夜写日记、四类记忆、承诺清单、注意力系统决定何时开口。
- **MIRROW** 把“活人感”做得最好：Memory V2、四路日结、心情、习惯与挂念、漫想、哨兵感知。
- **Open-LLM-VTuber** 把“存在感”做得最好：内心独白、主动说话、语音打断。
- **OpenClaw / Kodrik** 把“可扩展的长期助手”做得最好：持久记忆、心跳/定时主动、技能/数据集。

DeskMate 的机会不是再做一个“会看屏幕的桌宠”，而是把这三层接起来：**Dayflow 的时间线 + Miru 的记忆 + 一个懂程序员的习惯模型 + Haru 的陪伴感**。

## 1. 他们在“陪伴”上具体做了什么

### 1.1 Dayflow：自动工作日记

| 机制 | 具体做法 | 可借鉴点 |
|---|---|---|
| 自动时间线 | 轻量截屏 → AI 分析 → 生成按时间排列的 activity cards | 不要求用户手动计时；卡片是“做了什么”，不是“开了哪个 App” |
| Daily standup | 昨天 highlights、今天 priorities、blockers | 早上打开就知道“昨天停在哪、今天先干什么” |
| Weekly review | 专注时段、时间去向、App 占比、分心追踪 | 习惯不是靠猜，是靠一周的聚合 |
| 和日记对话 | “我这周在 auth 上花了多久？”基于 timeline 回答 | 长期记忆要能“问出来”，不只是存着 |
| Markdown 导出 | 任意日期范围导出 | 个人数据要能带走、能自己二次加工 |
| 本地优先 | 录屏/数据库留在 Mac；可选本地模型 | 隐私是个人陪伴产品的底线 |
| 自动清理 | 配置存储上限，自动清旧录屏 | 原始数据有保留期，摘要才长期保存 |

**关键细节：** Dayflow 把“Cursor 开了两小时”拆成“写功能 / 调 auth / 看 PR / 卡在环境”四种，而不是只记 App。这是“知道我在干什么”的核心。

### 1.2 Miru：午夜日记 + 四类记忆 + 承诺清单

| 机制 | 具体做法 | 可借鉴点 |
|---|---|---|
| 屏幕感知 | 默认 30 秒看一眼，没变化就跳过；只留“你在做什么”，不留截图 | 感知要轻、要可关、要能降频 |
| 午夜日记 | 到午夜把今天写进记忆 | 固定的“日结仪式”比随机总结更容易坚持 |
| 四类记忆 | 项目、人物、自己、话题 | 记忆按“关系”分类，不按“聊天记录”分类 |
| 承诺清单 | 从屏幕里读出“今晚把数字发你”，悄悄记下 | 陪伴感来自“它记得你答应过什么” |
| 注意力系统 | 读屏幕和节奏，判断此刻该不该开口；深度工作就安静 | 沉默是主动策略的一部分 |
| 可审计记忆 | 纯 Markdown，可打开、导出、删除 | 用户要能看见、能改、能删 |
| 人格文件 | `soul.md` 定义性格 | 人格与记忆分离，换人格不丢记忆 |

**关键细节：** Miru 的记忆不是“聊天摘要”，而是“项目/人物/自己/话题”四类可读的事实。这比向量库更适合个人长期使用，因为你能直接看懂它在记什么。

### 1.3 MIRROW：四路日结、心情、习惯与挂念

MIRROW 的公开说明里列了这些模块：Memory V2、认知与**四路日结**、**心情**、**习惯与挂念**、日历与任务、**漫想**、哨兵及感知采集、音乐耳蜗、语音。

这套东西的启发不是某个功能，而是“日结”不止一种：

- **事实日结**：今天做了什么。
- **情绪日结**：今天心情如何、为什么。
- **关系日结**：今天和谁有关、答应了什么。
- **认知日结**：今天想明白了什么、改了什么看法。

“习惯与挂念”也很妙：习惯是“你反复怎么做”，挂念是“你还没放下的事”。两者都比“待办列表”更像人。

“漫想”则是主动性的来源：不是等用户问，而是内部有一条缓慢的思绪流，遇到值得说的才开口。

### 1.4 Open-LLM-VTuber：内心独白 + 主动说话

- 屏幕上显示 AI 的“inner thoughts”，让用户看到它在想什么，而不是只看到最终回复。
- 主动说话（proactive speaking）+ 语音打断 + 桌面宠物模式。
- 聊天记录持久化，但长期记忆曾经被移除，说明“记忆”比“陪伴表现”难做。

**启发：** 陪伴感不只来自“说了什么”，也来自“它有自己的小念头”。但内心独白不能变成刷屏，最好只在气泡/面板里露出一小句。

### 1.5 Kodrik：日记/追踪器 + 每日主动

- 持久记忆、人格、可搜索的对话历史。
- 结构化的日记和 tracker 数据集，可查询、可汇总。
- 可选的“每日 Telegram 主动消息”，基于保存的兴趣和一次性提醒。
- 技能（skills）可以复用、自更新。

**启发：** 把“日记”做成结构化数据（日期、项目、情绪、能量、事件），而不是纯文本。这样后面才能挖习惯。

### 1.6 GranCyan：房间、日记、梦、共读

- “房间”里有日记、梦、学习/背单词、番茄钟、共读。
- 主动能力包括“偷看屏幕”、搜索、发图、点歌、看天气。
- 本地记忆库 + 向量粗召回 + 权重重排。

**启发：** 陪伴需要“共同活动”，不只是问答。一起读一本书、一起种一个番茄钟、一起回顾今天，都是关系素材。

### 1.7 ActivityWatch / Screenpipe：时间线与电脑史

- ActivityWatch：自动记录窗口/App/AFK，分类、时间线、隐私优先、可扩展。适合做“习惯”的底层数据。
- Screenpipe：连续记录电脑使用，目标是“Open Computer History”，可搜索、可映射工作流。

**启发：** 如果目标是“知道我一天干了什么”，窗口/App 时间线比截图更便宜、更准、更隐私；截图只用来补“具体在做什么”。

## 2. 十个可以直接借的机制

1. **自动时间线，不要手动计时。**  
   用户不会每天记得按开始/停止。用窗口 + 空闲 + 可选 OCR 自动切卡片。

2. **活动卡片，不是 App 列表。**  
   “9:10–9:55 在修 auth 的 race condition，跑了 3 次测试”比“VS Code 45 分钟”有用。

3. **固定日结仪式。**  
   每晚 22:00–23:00 之间，等用户空闲 5 分钟，生成 150–250 字日记；用户可改。改过的版本才是“记忆”。

4. **Daily standup 三件套。**  
   昨天 highlights、今天 priorities、当前 blockers。早上第一眼就能用。

5. **Weekly review 看模式，不看总量。**  
   “你周三下午最容易分心”“你每次改 auth 都先看 logs”比“本周 32 小时”有价值。

6. **四类记忆 + 承诺。**  
   项目、人物、自己、话题；再加“答应过的事”。承诺是最容易产生“它真的记得”的瞬间。

7. **候选习惯，不直接下结论。**  
   先输出“我发现……可能是……”，给证据和置信度，问一句“是吗？”。用户确认后再写入长期记忆。

8. **证据链。**  
   每句“你最近……”都能点开看到是哪几天的哪些事件。没有证据的记忆会变成幻觉。

9. **沉默是默认。**  
   深度工作、全屏、会议、正在输入、连续忽略两次 → 不说话。主动说话要有预算和冷却。

10. **可遗忘。**  
    原始事件 7–14 天，活动卡片 90 天，日结/习惯长期；支持按天删除、按 App 排除、一键清空。

## 3. 如果只给 DeskMate 做个人版，我会这样设计

> 实际落地的是 3.7 的轻量版；3.1–3.6 是更重的完整设想，留作以后，不是现在的默认形态。

### 3.1 三层数据

```
L1 原始事件（7–14 天）
  events: ts, app, title, url, ocr_excerpt, idle_sec, screenshot?(可选)

L2 活动卡片（90 天）
  episodes: start, end, category, summary, evidence, confidence

L3 长期记忆（永久，可删）
  daily_summaries: 日期、叙事、highlights、open_loops、focus_min、switches
  memories: fact / preference / habit / person / project / commitment
  habits: pattern, trigger, evidence, confidence, status(candidate/confirmed)
```

### 3.2 一天的循环

```
每 30–60 秒：记录窗口/空闲；窗口变化时抓一张低细节图 + 本地 OCR
每 5 分钟：判断是否还是同一个活动；是则延长，否则关闭一张卡片
每张卡片关闭时：先用规则/本地 OCR 打标签；晚上再批量让 LLM 写摘要
22:30：如果空闲，生成日结（150–250 字 + 3 个 highlights + 1 个 open loop）
日结后：问用户一个问题（“今天有什么事值得记住？”），用户回答后抽取记忆
周日 20:00：周结（时间去向、专注模式、分心触发、3 条候选习惯）
```

### 3.3 陪伴的四个时刻

| 时刻 | 触发 | 说什么 | 不说什么 |
|---|---|---|---|
| 早上第一次活跃 | 开机/解锁后 10 分钟 | “昨天你卡在 X，今天要不要先看 Y？” | 不报天气、不报日程流水账 |
| 中午卡住 | 同一错误/同一窗口 > 20 分钟，或 5 分钟内切窗 > 6 次 | “要不要把最近三次报错理一下？” | 不说“加油”“你可以的” |
| 晚上收尾 | 空闲 5 分钟 + 22:30 后 | 三句话日结 + 一个问题 | 不劝加班、不制造愧疚 |
| 周日晚上 | 周日 20:00 | 一条习惯洞察 + 一个问题 | 不列 20 条统计 |

### 3.4 习惯怎么挖

输入：最近 14 天的 `daily_summaries` + `episodes` +（可选）Git/测试信号。

输出候选，不输出结论：

```json
{
  "pattern": "你在上午 9:00–11:00 的 debug 效率明显更高",
  "trigger": "上午 + 有 failing test",
  "evidence": ["11-04 09:20-10:40 修复 auth", "11-06 09:10-10:30 修复 race"],
  "confidence": "medium",
  "question": "上午是不是你更习惯处理难 bug？"
}
```

规则：

- 至少 3 天证据才算候选。
- 候选状态最多保留 2 周；用户没确认就降权/删除。
- 用户确认后写入 `memories`，并记录“确认日期”。
- 反例要能推翻：用户说“不是”，就把这条标记为 rejected，不再提。

### 3.5 日结 prompt（可直接用）

```text
你是我的工作搭子。根据今天的活动时间线，写一份 150–250 字的日记。

要求：
1. 按“项目/任务”组织，不要按 App 罗列。
2. 写清楚：今天做了什么、卡在哪里、有什么没完成。
3. 只写时间线里有证据的事；不确定就写“可能”。
4. 最后用一句话问我一个具体问题，帮我回忆或决定明天先做什么。
5. 不要劝加班，不要用“加油”“你真棒”。

输出 JSON：
{
  "narrative": "...",
  "highlights": ["..."],
  "open_loops": ["..."],
  "question": "..."
}
```

### 3.6 周结 prompt（可直接用）

```text
根据最近 7 天的日结和活动卡片，找 3 条可能的习惯模式。

每条给出：
- pattern：一句话模式
- trigger：什么情况下发生
- evidence：至少 3 个日期/事件
- confidence：low / medium / high
- question：一个 yes/no 问题，帮我确认

只给候选，不要下结论。不要用“你应该”，用“我发现……可能……”。
```

### 3.7 实际落地的最小版本（已实现）

没有做全量时间线，只做了四件事：

| 能力 | 实现 |
|---|---|
| 每日锚点 | `anchors` 表；每天最多 8 条；聊天后从用户话里抽 1–2 条，也可在面板手动加 |
| 承诺 | `commitments` 表；从“今晚/明天/回头要……”里抽；面板可勾完成/删除 |
| 次日 callback | 6:00–14:00 第一次活跃，取昨天的锚点 / 最近 3 天未完成承诺，说一句；每天最多一次 |
| 晚间一句 | 22:00–02:00 空闲 ≥5 分钟，取今天的锚点，说一句 + 一个问题；每天最多一次 |
| 面板 | “今天” sheet：锚点、承诺、晚间一句；不做 dashboard |

刻意没做：全量时间线、活动卡片、习惯挖掘、周报、向量检索。

**之后补的增强（已实现）：**

- 自动锚点：测试红→绿、连续专注 60/90 分钟、测试红着卡住 30 分钟；每天最多 2 条，删了不会再自动生成。
- 闭嘴反馈：气泡关闭/点开回传；同类事件连续被关 2 次静默 7 天；全屏、会议、安静时段不主动说话。
- 声音与人格：macOS `say` 音色/语速可选；设置里写 persona（称呼/语气/边界/绝对不说）。
- 记忆修正：锚点可编辑；自动锚点 30 天衰减；长期记忆/锚点/承诺/日结可导出 JSON 或 Markdown。
- 面板：首屏加“今天”卡片；技术指标收进“诊断”；`Cmd+Shift+M` 直接“记一下”。

## 5. 不建议抄的东西

- **24/7  raw 录屏**：存储、隐私、性能都不适合个人长期跑；用窗口 + 按需截图 + OCR 就够。
- **streak / 打卡 / 愧疚机制**：会把“陪伴”变成“监督”。
- **过度主动**：Clippy 的问题不是不会说话，是不知道什么时候闭嘴。
- **假装人类/情感依赖**：个人用可以温暖，但不要用“离开你我很难过”这类话术。
- **只有摘要、没有证据**：用户问“你怎么知道”时答不上来，信任就没了。
- **一上来就向量库**：个人数据量小，SQLite FTS + 结构化字段 + 手动 pin 足够；语义检索可以后加。

---

## 6. 一句话

> 让 agent 知道你今天干了什么，靠的是**自动时间线**；让它长期知道你的习惯，靠的是**有证据、可修正、会遗忘的记忆**；让它像个搭子，靠的是**在该说话的时候说一句，其他时候安静**。

这三件事，Dayflow、Miru、MIRROW 各做对了一部分；DeskMate 可以把它们接起来，而且只为自己做，不需要考虑商业化。
